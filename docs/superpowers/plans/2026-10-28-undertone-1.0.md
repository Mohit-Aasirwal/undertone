# Undertone 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Undertone 1.0.0 with colour theming, beat detection, karaoke, visualizer modes, translations, smarter player handling, a D-Bus control surface, stats, a shared listening page, screensaver mode, Wayland support and distro packaging.

**Architecture:** `app.py` is split into focused modules (mpris, audio, sources, theme, modes, control, stats, web, idle). Pure logic stays in importable modules with unit tests; GTK and D-Bus glue stays thin. Every feature is config-driven under `~/.config/undertone/config.toml` and controllable at runtime over D-Bus via `undertone ctl`.

**Tech Stack:** Python 3.11+, GTK 3 via PyGObject, Gio D-Bus, numpy, sqlite3, http.server. Optional: GtkLayerShell (Wayland), libXss (idle).

**Spec:** the feature list agreed in chat (see CHANGELOG 1.0.0 once written). Execution rule from the user: each feature is tested end to end on this machine before the next starts.

## Global Constraints

- No new hard dependencies beyond numpy; optional integrations degrade gracefully when absent.
- Config keys documented in `config.example.toml` the moment they exist.
- Every task: unit tests green, `python3 -m unittest discover -s tests -t .`, then a live check (screenshot, `undertone ctl status`, curl, or D-Bus call), then a commit without attribution lines.
- Keep the two-monitor, 30 fps CPU budget near 10%.

## Review Focus

- A player publishing partial metadata (no album, no length, no art) must still show the lightbox and search lyrics. Pin in Task 8 tests.
- Network outages for any source must never block the UI thread or wedge the loading state. Pin in Task 8 (chain) and Task 9 (translation) tests.
- Offsets persisted per track must survive restart and apply before the first draw. Pin in Task 2 tests.
- Theme extraction on monochrome or tiny art must fall back to a usable accent, never black on black. Pin in Task 4 tests.
- Beat detection on silence or noise must emit no beats, not a steady false pulse. Pin in Task 5 tests.

---

### Task 1: Player allow/deny list
- Files: `undertone/player.py` (`pick_playing(statuses, allow=None, deny=None)`), `tests/test_player.py`, config `[players] allow = [] / deny = []` (substring match on the bus name after `org.mpris.MediaPlayer2.`).
- E2E: run with a test config denying `brave`, confirm window hides; allow `brave`, confirm it shows.

### Task 2: D-Bus control + offset nudging
- Files: `undertone/control.py` — owns `org.undertone` on the session bus, object `/org/undertone`, interface `org.undertone.Control` with methods `Toggle()`, `CycleVisualizer()`, `Nudge(ms: i) -> i`, `SetOffset(ms: i)`, `Status() -> s` (JSON). `undertone/offsets.py` — `Offsets(path)` with `get(track_key)`, `set(track_key, ms)`, `global_ms`; persisted to `~/.config/undertone/offsets.json`. CLI: `undertone ctl toggle|cycle-vis|nudge <ms>|offset <ms>|status`.
- Lyrics position = player position + global + per-track offset.
- E2E: `undertone ctl nudge 300`, `ctl status` shows offset 300, restart, status still 300 for same track.

### Task 3: Colour theming
- Files: `undertone/theme.py` — `palette_from_pixels(rgb_array) -> {"accent": (r,g,b), "base": (r,g,b)}` (downscale, drop near-grey/near-black, pick most saturated frequent hue; fallback accent (0.85,0.85,0.88)), `gtk_accent() -> (r,g,b)` via `theme_selected_bg_color`. Config `[theme] source = "art" | "gtk" | "none"`.
- Applied to: current line colour, ring stroke tint, a radial gradient behind the art.
- E2E: screenshot shows tinted current line; `ctl status` reports accent.

### Task 4: Beat detection
- Files: `undertone/beat.py` — `OnsetDetector(rate_hz)` with `feed(bass_energy) -> bool`; spectral-flux style: positive difference vs a running median threshold with 120 ms refractory. `tempo_estimate()` from onset intervals.
- Integrated in `AudioLevels`: `pulse` (0..1, decays over ~250 ms) and `bpm`.
- Rendering: rings kick outward by pulse, current line scales 1.0→1.04.
- E2E: play music, `ctl status` shows a plausible bpm within 60–200 and pulse > 0 at times; silence shows bpm 0.

### Task 5: Visualizer modes
- Files: `undertone/modes.py` — `draw_rings`, `draw_bars`, `draw_wave`, `draw_particles` with signature `(cr, cx, cy, max_r, levels, pulse, accent, opacity, state)`. Config `[visualizer] mode = "rings"`; `ctl cycle-vis` rotates; `MODES = ["rings","bars","wave","particles"]`.
- E2E: screenshot each mode after `ctl cycle-vis`.

### Task 6: Lyrics source chain + local .lrc
- Files: `undertone/sources.py` — `fetch_chain(track, sources, local_dirs) -> Lyrics`; sources: `local` (`<dir>/<artist> - <title>.lrc`, or `.lrc` beside `xesam:url`), `lrclib`, `netease` (search `music.163.com/api/search/get` → `api/song/lyric?lv=1`). Config `[lyrics] sources = ["local","lrclib","netease"]`, `local_dirs = ["~/Music"]`.
- Tests with stubbed HTTP; e2e: drop an .lrc for the current track into `~/Music`, see it used (status shows `source: local`).

### Task 7: Word-level karaoke
- Files: `undertone/lyrics.py` — `parse_lrc` keeps lines; new `parse_enhanced_lrc(text) -> list[(t, text, [(t_word, word)...])]`; `word_progress(words, pos) -> float 0..1`.
- Rendering: current line drawn twice, base colour then accent clipped to the sweep width.
- E2E: enhanced .lrc for current track in `~/Music`, screenshot mid-line shows partial sweep.

### Task 8: Translations
- Files: `undertone/translate.py` — `translate_lines(lines, target, cache_path)` using `translate.googleapis.com/translate_a/single?client=gtx` in a thread, cached per track. Config `[translation] enabled = false, target = "hi"`.
- E2E: enable, screenshot shows second faint line under current line.

### Task 9: Ken Burns backdrop + lyrics-free full visualizer
- Backdrop: cached art surface painted with a slow scale 1.0→1.08 over 40 s, ping-pong. Config `[backdrop] motion = true`.
- No lyrics: visualizer centred on full area, max radius bigger, notice moved to bottom.
- E2E: two frames 2 s apart differ in backdrop; forced-no-lyrics config screenshot.

### Task 10: Screensaver mode
- Files: `undertone/idle.py` — `idle_seconds()` via XScreenSaver (ctypes libXss), returns 0 on failure; env `UNDERTONE_FAKE_IDLE` overrides for testing. Config `[screensaver] enabled = false, idle_minutes = 10`.
- Behaviour: above threshold, windows switch to `keep_above` + type NORMAL; on activity, back to desktop layer.
- E2E: fake idle → stacking order shows windows on top; unset → back below.

### Task 11: Stats
- Files: `undertone/stats.py` — sqlite `~/.local/share/undertone/history.db`, table `plays(ts, title, artist, album, length_s, source)`; record on track change after 30 s of play. CLI `undertone stats [--days N]` prints top artists/tracks, total time.
- E2E: play, run `undertone stats`.

### Task 12: Shared listening page
- Files: `undertone/web.py` — `http.server` on `[web] enabled = false, port = 8765, bind = "0.0.0.0"`; `/` serves a single HTML page, `/events` SSE stream of `{title, artist, art_url, lines, idx, accent}`, `/art` proxies current art.
- E2E: curl `/events` shows events; open page in Chrome screenshot.

### Task 13: Wayland (layer shell)
- `Lightbox` uses `GtkLayerShell` when `Gdk.Display` is Wayland and the typelib imports: layer BACKGROUND (or TOP in screensaver mode), anchored to all edges, per-monitor.
- E2E: nested `sway` headless if installable; otherwise document as untested.

### Task 14: Packaging
- `packaging/build-deb.sh` producing `undertone_<ver>_all.deb` (depends python3-gi, gir1.2-gtk-3.0, python3-numpy, pulseaudio-utils); `packaging/PKGBUILD`; `packaging/io.github.mohitaasirwal.Undertone.yml` flatpak manifest; CI uploads the .deb on tags.
- E2E: build .deb locally, `dpkg -c`, `dpkg-deb -I`; `bash -n PKGBUILD`.

### Task 15: Release 1.0.0
- Bump version, CHANGELOG, README (features, config, ctl, stats, web), config.example.toml complete; tag, push, release.
